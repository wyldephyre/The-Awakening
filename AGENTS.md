# The Awakening — All Out (CSL) game

This repository is an **All Out** game (`ao.project` has `csl: true`). Gameplay is written in
**CSL** (a statically-typed language that feels like Go/Odin) under `scripts/`, with generated
engine API stubs under `api_references/core/**/*.csl_engine`. See the official docs at
https://docs.allout.game (index: https://docs.allout.game/llms.txt).

## Cursor Cloud specific instructions

Read this before trying to "install dependencies", "build", "run", or "lint" in a Cursor Cloud
Linux VM — the normal expectations do not apply to this project.

### The toolchain is Windows-only and cannot run in this Linux VM

- All Out games are built/run with the **All Out editor**, a downloadable **Windows** program that
  bundles the CSL compiler (`csl.exe`) and the engine runtime. There is **no Linux or macOS build**
  of the editor, and `csl.exe` is not distributed as a standalone/headless Linux binary.
- CSL scripts compile against native engine functions declared as `#foreign "..."` in
  `api_references/core/**/*.csl_engine` (e.g. `#foreign "game_get_local_player"`). Those symbols
  are only implemented inside the running All Out engine, so scripts **cannot be compiled or
  executed outside the editor** — not under Node, .NET, Wine, etc.
- The `allout` MCP server in `.cursor/mcp.json` (`http://localhost:3333/mcp`) is started
  automatically **by the editor** and is used for compile/error feedback and asset fetching. In a
  Cursor Cloud VM there is no editor, so port 3333 is not serving and MCP compile checks are
  unavailable.

Consequence: in this environment there is **no build, no run, no automated tests, and no lint**.
Do not attempt to install a CSL/AO toolchain here — none exists for Linux.

### There are no installable dependencies

- No `package.json` / `requirements.txt` / lockfiles / `Makefile` / build scripts exist, and none
  should be added. `Assembly.csproj`, `bin/`, `obj/`, `generated/`, and `MyPlayer.cs`'s `AO`
  namespace are **generated by the editor** (see `.gitignore`), not produced by any command here.
- The environment update script is intentionally a no-op.

### What you CAN do in a Cursor Cloud VM

- Read and edit `.csl` files in `scripts/`. Keep imports centralized in `scripts/main.csl` (folder
  imports, not per-file), per All Out convention.
- Validate code **by hand** against the API surface in `api_references/core/**/*.csl_engine`
  (the latest `core.csl`/stdlib surface) and the docs. This is the only "checking" available here.
- Follow CSL best practices: store per-player state on `Player` (avoid global gameplay state); use
  `is_local()` for cosmetic/local-only UI and `is_local_or_server()` for gameplay inputs; UI draw
  calls must run inside the player update/late-update context.

### How to actually build / run / test (outside this VM)

- Local: open the game from the All Out **Creator Portal → Edit** on a **Windows PC**; the editor
  compiles and playtests it. `csl.exe` compiles+runs by default; `csl.exe -no_run` is compile-only.
- Cloud: use All Out's own **Cloud Build** (a hosted VM running the editor), which can be linked to
  this Git repo. This is a separate product from Cursor Cloud Agents.

Note: `AGENTS.md` is listed in `.gitignore` (the editor generates its own copy locally). This file
is force-tracked so future Cursor Cloud agents inherit these notes.
